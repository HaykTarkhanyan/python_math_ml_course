# Downloading GPT-2 from the Hub: the xet path returned 404; `HF_HUB_DISABLE_XET=1` worked

**Symptom.** On 2026-11-06, `snapshot_download("gpt2", allow_patterns=[..., "model.safetensors", ...])` with
huggingface_hub 1.27.0 failed:

```
ConnectionError: Network error: Request error: HTTP status client error (404 Not Found),
domain: https://huggingface.co/api/models/gpt2/xet-read-token/607a30d783dfa663caf39e06633721c8d4cfcd7e
```

**Fix.** The same call with `HF_HUB_DISABLE_XET=1` set downloaded all files (about 550 MB) into the usual cache
folder `models--gpt2/`, where `embeddings_position_figs.py` and `llm_roadmap.py --gpt2` look for them.

**Cause (not confirmed).** The xet transfer asked for a read token under the legacy alias `gpt2` (the repo is
`openai-community/gpt2` now) and got 404. The plain HTTP download follows the alias. Not tested: whether the full
id `openai-community/gpt2` works over xet. It would also cache under a different folder name, which the scripts do
not look in.

**Consequences.** If a GPT-2 download fails with a `xet-read-token` 404, rerun it with `HF_HUB_DISABLE_XET=1`
rather than switching repo ids. The figure script's docstring says so.
