From a job ad to checked JSON¶

Practical after the API notebook.

One of the most common jobs for an LLM in a company is a boring one: turn messy text into a row of a database. Invoices, contracts, emails, job ads. The industry calls it document AI or information extraction. Today we do it on real data: the 148 job postings from staff.am that the course collected on 28 October 2026, read by four cheap models (GPT-4o mini, DeepSeek V4.1 Flash, Gemma 4 26B, Llama 3.1 8B) and, for comparison, one flagship: GPT-6.1 Sol.

Three ideas from LLM-2 (Decoding) become tools here:

  • constrained decoding: a strict JSON schema, so every reply is valid JSON;
  • log-probabilities: a confidence score for a field, so unsure answers can go to a person;
  • temperature 0: which, as LLM-2 warned, is not quite deterministic.

The plan: the data (1), the schema (2), a confidence number (3), providers (4), one call (5), all 148 postings (6), then the measurements: a baseline (7), asking for JSON vs a strict schema (8), the models side by side (9), a review queue (10), Armenian vs English (11), temperature 0 twice (12), and the question that matters: would you ship it? (13)

Running it. The calls were made once and saved (results/job_extraction_calls.json, 2026-11-11): 1,776 for the cheap models ($0.39) and 148 for GPT-6.1 Sol ($0.36). Re-executing reads the saved run and makes only 5 live calls: about a minute, about half a cent. RERUN = True repeats everything.

1. The data

Every posting has free text (title, description, responsibilities, qualifications) and some fields the employer filled in on the site: seniority level, salary, a "remote" tick box. The model gets the text only.

Where the postings come from. The course's job-market study scraped them on 28 October 2026 with _knowledge/ml_job_market/py_src/collect_staffam.py (5.4 minutes, 177 requests, one every 1.5 s). staff.am's own keyword search is fuzzy, so the script does not search: it walks every listing page (staff.am/en/jobs?page=N, 50 jobs per page), keeps a job if its title matches one of the study's ML / AI / data role patterns or it sits in an IT or data category, and then opens each kept job's own page.

No HTML parsing is needed. staff.am is built with Next.js, which puts each page's data as JSON into one <script id="__NEXT_DATA__"> tag, every text in English, Armenian and Russian. The core of the scraper:

3. A confidence number from logprobs

With logprobs=True the API sends, next to the reply, one entry per generated token: the token's text, its log-probability, and the 5 tokens it beat. That is a probability per token, and we want one per field.

For seniority the bridge is easy. The schema allows only five values, so the model's first token of the value ("jun", "mid", "sen", "lead", "not") is a choice among very few options, and its probability is a confidence score for exactly that field (LLM-2, "Why log-probabilities"). The work is finding which entry that is.

The reply is one string, {"seniority":"junior",...}; the entries are its pieces: {", sen, ior, ity, ":", jun, ior, ... Searching the entries for the text "jun" does not work in general: GPT-4o mini writes "jun" + "ior", Gemma writes "junior" as one token, so the text to look for depends on the tokenizer. The position does not. The function:

  1. glues the pieces back together and checks that they spell the reply;
  2. finds the byte where the seniority value starts, just after "seniority": " (spaces and line breaks allowed: Gemma and Llama spread their JSON over several lines);
  3. walks the pieces, adding up their lengths, until one covers that byte. That entry is the answer.

Lengths are counted in bytes, not characters: an Armenian letter is 2 bytes in UTF-8, and a token can end in the middle of one (LLM-1). Two provider quirks are allowed for: some providers append the model's end marker (Gemma's <eos>, DeepSeek's <｜end▁of▁sentence｜>) as a last "token", stripped first; and Llama's endpoint leaves out the first few tokens, so the pieces spell only the end of the reply. If the pieces match the reply in neither way, the function returns None instead of guessing.

In [16]:
# end-of-text markers some providers send as a last "token" (Gemma, Llama, DeepSeek, ...)
END_MARKS = re.compile(r"(<eos>|<\|eot_id\|>|<\|end_of_text\|>|<\|im_end\|>|<\|endoftext\|>|</s>|<｜end▁of▁sentence｜>)+$".encode())


def seniority_token(content, lp):
    # the logprob entry of the seniority value's first token, or None
    if not lp:
        return None
    # 1. the pieces, glued back together, must spell the reply
    pieces = [bytes(t.bytes) if t.bytes is not None else t.token.encode("utf-8") for t in lp]
    joined, reply = END_MARKS.sub(b"", b"".join(pieces)), content.encode("utf-8")
    if reply.startswith(joined):
        start = 0                                            # the usual case
    elif reply.endswith(joined):
        start = len(reply) - len(joined)                     # the first tokens have no entries (Llama)
    else:
        return None                                          # they do not match: no guessing
    # 2. the byte where the seniority value begins, right after '"seniority": "'
    m = re.search(r'"seniority"\s*:\s*"', content)
    if not m:
        return None
    target = len(content[:m.end()].encode("utf-8"))
    # 3. walk the pieces, adding up their lengths, until one covers that byte
    for t, piece in zip(lp, pieces):
        if start <= target < start + len(piece):
            return t
        start += len(piece)
    return None


def confidence(content, lp):
    t = seniority_token(content, lp)
    return math.exp(t.logprob) if t else None

def parse(content):
    try:
        obj, how = json.loads(content), "clean"
    except json.JSONDecodeError:
        m = re.search(r"\{.*\}", content, re.S)
        if not m:
            return None, "not JSON"
        try:
            obj, how = json.loads(m.group(0)), "needed cleanup"
        except json.JSONDecodeError:
            return None, "not JSON"
    try:
        Job.model_validate(obj, strict=True)
    except ValidationError:
        return obj, "breaks schema"
    return obj, how

def extract(model, mode, job):
    t0 = time.time()
    kw = dict(model=model, max_tokens=4000 if model == STRONG else 1000, extra_body=EXTRA[model],
              messages=[{"role": "system", "content": SYSTEM if mode == "schema" else PROMPT_ONLY},
                        {"role": "user", "content": text_of(job)}])
    if model != STRONG:
        kw.update(temperature=0, logprobs=True, top_logprobs=5)
    if mode == "schema":
        kw["response_format"] = {"type": "json_schema",
                                 "json_schema": {"name": "job_posting", "strict": True, "schema": SCHEMA}}
    try:
        r = client.chat.completions.create(**kw)
    except Exception as e:                                   # kept and counted as a failed call
        return {"error": f"{type(e).__name__}: {str(e)[:300]}", "secs": round(time.time() - t0, 2)}
    d, choice = r.model_dump(), r.choices[0]
    u, content = d.get("usage") or {}, choice.message.content or ""
    lp = choice.logprobs.content if choice.logprobs and choice.logprobs.content else []
    tok = seniority_token(content, lp)
    return {"content": content, "finish": choice.finish_reason, "provider": d.get("provider"),
            "prompt_tokens": u.get("prompt_tokens"), "completion_tokens": u.get("completion_tokens"),

ENTRY_T = re.compile(r"\b(intern|internship|junior|jr\.?|trainee|entry|graduate|student)\b", re.I)

def years_min(text):
    found = [int(m.group(1)) for m in YEARS.finditer(text)
             if EXPERIENCE.search(text[max(0, m.start() - 60): m.end() + 60]) and 0 < int(m.group(1)) <= 20]
    return min(found) if found else None
