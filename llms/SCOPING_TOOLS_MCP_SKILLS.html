Scoping notes, 2026-11-12, before any outline or code (DECISIONS #115). Web facts were checked today; where a fact rests on secondary sources it says so. The session runs 20:00 to 22:00 Yerevan time.

Q15 notebook for everyone plus an instructor demo in a real MCP client. Outline draft: llms/03_tools_agents/05_06_tools_agents_OUTLINE.md.
In short
  • Half of it exists. L44 (ml/ch18_agents/L44_agents_tools.tex, 37 pages) already has the ladder: direct orchestration, tool calling, MCP, skills, the agent loop, choosing. Its hands-on source deck, with runnable OpenRouter code for every rung, is deleted but still in git.
  • The code side got easier. The MCP Python SDK v2 lets a notebook run a real MCP server in the same process (Client(server)): no subprocess, no port, no Windows trouble. OpenRouter passes tool calls through and can list which models support them.
  • The world moved since L44 was written (August, reviewed October): a new MCP spec (2026-07-28), Skills as an open standard read by Codex and others, fixes for "too many tool schemas" (tool search, code execution with MCP), and MCP security incidents. L44 needs a few new frames, not a rewrite.
  • It is a lot for two hours. My lean: two sessions. Session 1, "the model decides, your code does" (tool calls and the loop). Session 2, "tools you did not write, knowledge on demand" (MCP, skills, orchestration patterns, security).
  • Decisions for you are in section 7 (Q10 to Q15).

2. What changed since L44 was written
TopicWhat is true nowFor the session
MCP specLatest revision 2026-07-28. Reported changes: a stateless core (each request carries its own context, any server instance can answer), Roots, Sampling and Logging deprecated, Tasks and MCP Apps moved to extensions, tighter authorization. The project is now under the Linux Foundation; a roadmap followed on 2026-08-22. change details from secondary write-ups; the spec page lists 2026-07-28 as latest L44's "what travels" frame (tools/list, tools/call) still holds. One new frame: what MCP is in late 2026.
MCP Python SDKv2: the server class is MCPServer (formerly FastMCP); Client(x) takes a URL (Streamable HTTP), a subprocess description (stdio), or the server object itself, in memory, and every call still goes through the real protocol layer.The notebook can run server and client in one kernel. A real client (Claude Desktop, VS Code) becomes an instructor demo, not a student setup step.
SkillsReleased by Anthropic in October 2025; an open standard since 18 December 2025 (agentskills.io). About 30 to 40 tools read SKILL.md, among them OpenAI's Codex CLI (.agents/skills/) and Gemini CLI. counts from secondary sourcesSkills are no longer one vendor's feature: worth saying. L44's mechanism frames still hold.
Too many tool schemasAnthropic, November 2025: a Tool Search Tool (definitions loaded on demand; reported ~85% fewer definition tokens on MCP-heavy work) and Programmatic Tool Calling. Same month: "Code execution with MCP" (2025-11-04), presenting MCP servers as code APIs the agent calls from a sandbox; Cloudflare reached the same idea ("Code Mode").L44's "cost nobody mentions" frame now has an answer. One frame, and a nice by-hand demo: search the tools, load three.
SecurityTool poisoning (instructions hidden in a tool's description, which the model reads as trusted), injection through tool results, servers changing their definitions after approval. Simon Willison's lethal trifecta: private data + untrusted content + a way to send data out. Surveys report many vulnerable public servers and skills. survey numbers unverifiedL44 covers injection through text the loop did not write. Add tool poisoning and the trifecta as a checklist.
Orchestration patternsAnthropic's "Building effective agents" (2024-12-19) splits workflows (your code fixes the steps: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer) from agents (the model picks the next step), and says to start with the simplest that works. Subagents with their own context are the common 2026 form of orchestrator-workers.L44 has "direct orchestration" as its first rung but not these patterns. If "orchestration" means them, that is new material (Q10).
Tool calling on OpenRoutertools, tool_choice (including forcing one tool), parallel_tool_calls (default on); /models?supported_parameters=tools lists models with tool support; the Responses API also takes tools.Same client as B0. Test endpoints first, as before: a claimed feature is not a delivered one (the B0b lesson).
Small models and toolsLeaderboards disagree (BFCL v3 and v4 are not comparable, third-party tables conflict). One consistent theme: multi-turn tool use is where small models break.Pick models by a short test of our own; show one small model failing a multi-step task on purpose.
Free clients for studentsGemini CLI's free personal tier reportedly ended on 2026-06-18 (replaced by Antigravity). Claude Desktop runs local MCP servers; VS Code with Copilot is free through GitHub Education. secondary sourcesDo not make a client install a prerequisite; the in-memory notebook route works everywhere.

Models

Same approach as B0: pin providers, test before trusting. A cheap reliable tool caller (GPT-4o mini or similar), one open model with tool support, and one small open model to show where multi-step tool use breaks. The test is a short script, cents not dollars; the model list is chosen after it runs.

6. Risks
  • Live tool calls fail in class. Save every run (the B0 pattern) so a re-execution reads saved calls, with a few live calls only.
  • Async in a notebook. The MCP client is async; Jupyter allows top-level await, but nested event loops on Windows can bite. To test early.
  • Staleness. MCP and the SDK changed twice this year. Pin versions with == and re-run before teaching.
  • Overlap with later sessions. The agents workshop (B6) and the plan page's B2 cover the same ground. This session would absorb B2 and most of B6; the plan page needs updating once scoped.
  • L44 and the LLM part. L44 lives in ml/ch18_agents and was written for the old order (after RAG). Its callbacks to RAG decks need checking if it is used before RAG.
