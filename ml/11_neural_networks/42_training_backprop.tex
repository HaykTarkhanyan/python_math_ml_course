% --- OUR SPRINKLE (after the by-hand backprop): the clean residual ---
\begin{frame}{A cleaner residual: the output gradient is $f - y$}
  LMU used the \textbf{L2 loss} on class labels to keep the algebra simple. In practice,
  classification uses \textbf{cross-entropy} -- and then the output-layer gradient collapses to
  something you already know:
  \begin{align*}
    \text{sigmoid} + \text{cross-entropy} &\;\Longrightarrow\;
      \frac{\partial L}{\partial f_{\text{in}}} = f - y \\
    \text{softmax} + \text{cross-entropy} &\;\Longrightarrow\;
      \frac{\partial L}{\partial \mathbf{f}_{\text{in}}} = \mathbf{p} - \mathbf{y}
      \quad(\text{one-hot } \mathbf{y})
  \end{align*}
  {\small \textbf{Why not L2?} Its gradient keeps a $\sigma'(f_{\text{in}})$ factor, which is tiny
  exactly when the net is confidently wrong. Take $f = 0.01$ with $y = 1$: L2 gives
  $-(1-0.01)\cdot 0.01\cdot 0.99 \approx -0.0098$, cross-entropy gives $f - y = -0.99$, a push
  a hundred times stronger.}
  \vfill
  \fcolorbox{armblue}{armblue!8}{\parbox{0.97\linewidth}{\small
    \textbf{The same ``residual'' from earlier in the course.} Linear regression, logistic
    regression, and now a neural net: the output signal is \textbf{prediction $-$ target}.
    Everything to its left is that residual, passed backward and scaled by local derivatives.}}
\end{frame}

% --- OUR SPRINKLE (after the residual): what p - y does to the logits (Karpathy's push & pull) ---
\begin{frame}{The softmax gradient as push and pull}
  \small
  The softmax example from the multilayer-nets deck: logits $(0.57,\ 2.95,\ -0.92)$ give
  $\mathbf{p} = (0.08,\ 0.90,\ 0.02)$. The gradient on the logits is $\mathbf{p} - \mathbf{y}$, and
  a descent step moves each logit \emph{against} it:
  \vskip 2pt
  \begin{center}\includegraphics[width=0.95\linewidth]{fig/softmax_push_pull.pdf}\end{center}
  \vskip -2pt
  \begin{itemize}\footnotesize
    \item The correct class is \textbf{pulled up} by $1 - p_{\text{correct}}$; every wrong class is
      \textbf{pushed down} by its own $p$. The pushes and the pull cancel: each row sums to $0$.
    \item The force is exactly how wrong the net was: right and confident, a nudge; confidently
      wrong, a shove. A perfect prediction gets no gradient at all.
  \end{itemize}
  \vfill
  {\scriptsize\color{gray} Intuition: Karpathy, \emph{Becoming a Backprop Ninja} (2022).}
\end{frame}

% --- OUR SPRINKLE (after the recursion): its cost -- vanishing gradients ---
\begin{frame}{What this recursion costs: vanishing gradients}
  LMU's recursion $\;\delta^{(i)} = \mathbf{W}^{(i+1)}\delta^{(i+1)} \odot
  \sigma'(\mathbf{z}^{(i)}_{\text{in}})\;$ multiplies by $\sigma'$ at \emph{every} layer on the
  way back -- and that factor is small:
  \vfill
  \begin{columns}[T]
    \column{0.52\textwidth}
    \begin{center}\includegraphics[width=\linewidth]{fig/activation_grads.pdf}\end{center}
    \column{0.48\textwidth}
    \begin{itemize}\footnotesize
      \item Sigmoid: $\sigma'\le 0.25$. Over $k$ layers the $\sigma'$ factors alone give
        $\le 0.25^{k}$ -- unless the weights grow to compensate, the gradient
        \textbf{vanishes exponentially}.
      \item $0.25^{10}\approx 10^{-6}$: over $10$ sigmoid layers those factors alone shrink it at
        least a \emph{millionfold}.
      \item \textbf{ReLU} ($\sigma'=1$ for $z>0$) largely fixes this -- the default hidden
        activation.
    \end{itemize}
  \end{columns}
  \vfill
  \fcolorbox{armred}{armred!8}{\parbox{0.97\linewidth}{\small
    The \textbf{vanishing-gradient} problem is a direct consequence of the backprop recursion
    LMU just derived -- and a big reason deep nets were hard to train before ReLU.}}
\end{frame}

% --- OUR SPRINKLE (after the software pages): autograd reproduces the by-hand XOR pass ---
\begin{frame}[fragile]{The whole by-hand pass in one call: \texttt{loss.backward()}}
  \small
  LMU's XOR network, same weights, $\mathbf{x} = (1, 0)$, $y = 1$, in PyTorch:
  \vskip 2pt
\begin{lstlisting}
x = torch.tensor([1., 0.]); y = 1.0
W = torch.tensor([[-0.07, 0.22], [0.94, 0.46]], requires_grad=True)
b = torch.tensor([-0.46, 0.10], requires_grad=True)
u = torch.tensor([-0.22, 0.58], requires_grad=True)
c = torch.tensor(0.78, requires_grad=True)

# forward pass
f = torch.sigmoid(u @ torch.sigmoid(W @ x + b) + c)
loss = 0.5 * (y - f) ** 2
# backward pass: every gradient at once
loss.backward()
# f = 0.7553,  u.grad[0] = -0.0168,  W.grad[0, 0] = 0.0023
\end{lstlisting}
  \vfill
  \fcolorbox{armblue}{armblue!8}{\parbox{0.97\linewidth}{\small
    Twenty pages of chain rule, one line of code. PyTorch agrees with the \emph{corrected} forward
    pass ($f = 0.7553$); LMU's pages, built on $0.7525$, show $-0.0171$ and $0.0024$ for the same
    two gradients.}}
\end{frame}

% --- OUR SPRINKLE (after autograd): why we still learned backprop by hand (Karpathy, 2016) ---
\begin{frame}{Then why learn backprop at all? It is a leaky abstraction}
  \small
  \texttt{loss.backward()} returns correct derivatives of whatever you wrote. Whether they are
  \emph{useful} depends on what flows backward -- ``backpropagation is a leaky abstraction''
  (Karpathy, 2016):
  \vfill
  \begin{itemize}\footnotesize
    \item \textbf{Saturation:} in the flat tails of sigmoid and tanh the local derivative is
      $\approx 0$, so the gradient stops there (the vanishing-gradient frame).
    \item \textbf{Dead ReLUs:} a unit that is negative for every input gets zero gradient forever --
      from initialization, or after a too-large update knocks it off the data.
    \item \textbf{Exploding gradients:} multiply by the same weight matrix step after step, as a
      recurrent net does, and the gradient can blow up (RNN chapter).
    \item \textbf{A real bug:} a deep Q-learning implementation clipped its error term to tame
      outliers. Clipping has local derivative $0$ outside its range, so exactly those examples got
      \emph{zero} gradient and were silently ignored. The fix: the Huber loss.
  \end{itemize}
  \vfill
  \fcolorbox{armred}{armred!8}{\parbox{0.97\linewidth}{\small
    Autograd never complains: the code runs and the gradients are ``correct''. Knowing the
    backward pass is how you notice they are useless.}}
\end{frame}

\begin{frame}{Will it fit? Memory before you rent}
  \small
  Count \textbf{bytes per weight}. A full-precision number takes $4$ bytes, a half-precision
  one $2$. Training with Adam in mixed precision needs about \textbf{16 bytes per weight}
  (Rajbhandari et al., 2020):
  \[
    \underbrace{2}_{\text{fp16 weights}} + \underbrace{2}_{\text{fp16 gradients}} +
    \underbrace{4 + 4 + 4}_{\text{fp32 weights, Adam's } m,\ v} = 16
  \]
  \vskip -2pt
  \begin{center}\footnotesize
  \begin{tabular}{@{}l r r r@{}}
    \textbf{model} & \textbf{weights} & \textbf{run (2 B/weight)} & \textbf{train (16 B/weight)} \\ \hline
    homework MLP & $0.24$M & $0.5$ MB & $4$ MB \\
    GPT-2 small & $124$M & $0.25$ GB & $2$ GB \\
    GPT-2 XL & $1.5$B & $3$ GB & $24$ GB \\
    7B language model & $7$B & $14$ GB & $\mathbf{112}$ \textbf{GB} \\
  \end{tabular}
  \end{center}
  \vfill
  \fcolorbox{armorange}{armorange!12}{\parbox{0.97\linewidth}{\small
    Activations come \emph{on top} and grow with the batch size. So one 80 GB H100 trains at most
    about a 5B-parameter model the plain way; the 7B model does not fit. Adam's two moment
    vectors alone are 8 of the 16 bytes -- the optimization deck shows where they come from.}}
\end{frame}

\begin{frame}{Renting without getting burned}
  \begin{itemize}\footnotesize
    \item \textbf{The meter runs while the machine is on,} busy or idle. Stop it when you are done;
      stored disks are often still billed after that.
    \item \textbf{The disk can vanish.} A Colab runtime or a cloud container is wiped when it
      stops. Save checkpoints and results somewhere persistent, often.
    \item \textbf{Expect interruptions.} Colab disconnects, spot instances get reclaimed: checkpoint
      every few epochs so a restart resumes instead of starting over.
    \item \textbf{Check you actually got the GPU:} \texttt{nvidia-smi} in a terminal, then
      \texttt{device = "cuda" if torch.cuda.is\_available() else "cpu"}, and move \emph{both} the
      model and every batch with \texttt{.to(device)}.
    \item \textbf{Keys never go in a notebook.} API keys (W\&B, Hugging Face) belong in environment
      variables or the platform's secrets manager: notebooks get shared and screenshotted.
  \end{itemize}
  \vfill
  \fcolorbox{paramgreen}{paramgreen!8}{\parbox{0.97\linewidth}{\small
    \textbf{Debug where it is free.} Run one epoch on a tiny subset on your laptop or a free
    notebook first; rent the big GPU only for a run you already trust.}}
\end{frame}

\begin{frame}{Recap: how a network learns}
  \begin{itemize}\small
    \item \textbf{Objective:} minimise the empirical risk by \textbf{gradient descent};
      \textbf{SGD} does it on mini-batches -- cheaper, noisier, and often generalises better.
    \item \textbf{Backprop} $=$ the chain rule on the computational graph, run \emph{backward
      once}. Each layer's error signal $\delta$ is computed from the layer above and reused:
      ``$\delta\times$ local derivative'', ``$\delta\times$ input''.
    \item That reuse is why \emph{one} backward pass gives \textbf{all} gradients -- the naive
      alternative is one forward pass per weight.
    \item \textbf{You won't code it by hand:} frameworks (PyTorch, TensorFlow) build the graph
      and run backprop when you call \texttt{loss.backward()} -- on \textbf{GPUs/TPUs} that do
      the matrix math massively in parallel, rented by the hour and with every run tracked.
  \end{itemize}
  \vfill
  \fcolorbox{paramgreen}{paramgreen!8}{\parbox{0.97\linewidth}{\small
    We can now \emph{train} a network. What remains: keeping it from \textbf{overfitting}
    (regularization), and \textbf{optimizing} faster than plain SGD -- the next two chunks.}}
\end{frame}
